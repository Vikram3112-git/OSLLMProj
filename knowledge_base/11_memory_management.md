# Memory Management: Basics, Contiguous Allocation, Paging and Segmentation

## Address binding
Instructions and data can be bound to memory addresses at:
- Compile time: absolute code is generated; the program must be recompiled if its start address changes.
- Load time: relocatable code; addresses are fixed when the program is loaded.
- Execution time: binding is delayed until run time, so the process can be moved in memory during execution. This needs hardware support (an MMU) and is what modern systems use.

## Logical and physical addresses
A logical (virtual) address is generated by the CPU; a physical address is the one seen by the memory unit. With compile-time and load-time binding they are the same; with execution-time binding they differ. The memory-management unit (MMU) maps logical addresses to physical addresses at run time.

Relocation and limit registers: the relocation (base) register holds the smallest physical address of the process and the limit register holds the size of its logical address space. Every logical address is first checked: if logical address < limit, physical address = relocation + logical address; otherwise the hardware traps to the OS (addressing error). Example: relocation 14000, limit 3000: logical address 346 → physical 14346; logical address 3500 → trap.

Dynamic loading: a routine is loaded only when it is first called. Dynamic linking: linking to system libraries is postponed until run time (shared libraries, .so or .dll), so one copy in memory is shared by many programs. Swapping: a process can be moved temporarily to a backing store and brought back later; standard swapping of whole processes is slow, so modern systems swap pages, and mobile systems usually avoid swapping.

## Contiguous memory allocation
Each process occupies one contiguous block of memory.
- Fixed partitions: memory is divided into partitions of fixed size; each holds one process. Leads to internal fragmentation (unused space inside a partition).
- Variable partitions: the OS keeps a list of free blocks (holes) and gives each process a hole of the needed size, splitting the hole. Leads to external fragmentation (enough total free memory, but in pieces that are too small).

Dynamic storage-allocation strategies (course convention: the chosen hole is split and the remainder stays free; next fit resumes its search at the hole used last):
- First fit: the first hole that is big enough. Fast.
- Best fit: the smallest hole that is big enough. Leaves the smallest leftover, but must search the whole list.
- Worst fit: the largest hole. Leaves the largest leftover, which may be useful later; must search the whole list.
- Next fit: like first fit, but starts searching where the previous search ended.
First fit and best fit are better than worst fit in time and storage use; first fit is usually as good as best fit and faster.

## Worked example (solved exactly by OSLLM's solver)
Holes in order: B1 = 100 KB, B2 = 500 KB, B3 = 200 KB, B4 = 300 KB, B5 = 600 KB. Processes in order: P1 = 212 KB, P2 = 417 KB, P3 = 112 KB, P4 = 426 KB.
- First fit: P1 → B2 (288 KB left), P2 → B5 (183 KB left), P3 → B2 (176 KB left), P4 must wait: no hole is 426 KB or larger, even though 959 KB is free in total (external fragmentation).
- Best fit: P1 → B4 (88 left), P2 → B2 (83 left), P3 → B3 (88 left), P4 → B5 (174 left). All four fit.
- Worst fit: P1 → B5 (388 left), P2 → B2 (83 left), P3 → B5 (276 left), P4 must wait.
- Next fit: P1 → B2, P2 → B5, P3 → B5 (search resumes at B5, which still has 183 KB), P4 must wait.

Fragmentation: the 50-percent rule says that with first fit, about N/2 blocks are lost to external fragmentation for N allocated blocks (one third of memory may be unusable). Compaction moves processes together to make one large hole, but it needs execution-time binding and is expensive. Paging and segmentation solve external fragmentation by allowing non-contiguous allocation.

## Paging
Physical memory is divided into fixed-size frames and logical memory into pages of the same size. Any page can go in any free frame; a page table maps page numbers to frame numbers.

Address translation: with page size 2^n bytes, a logical address is split into page number p = address div 2^n (the high bits) and offset d = address mod 2^n (the low n bits). Physical address = frame(p) × page size + d.
Example: page size 1 KB (1024 bytes) and page table [page 0 → frame 5, page 1 → frame 2, page 2 → frame 7, page 3 → frame 9]. Logical address 3085: p = 3085 div 1024 = 3, d = 3085 − 3072 = 13; frame 9; physical address = 9 × 1024 + 13 = 9229.

Paging has no external fragmentation, but there is internal fragmentation in the last page of a process (on average half a page). Page-table size: with 32-bit logical addresses and 4 KB pages there are 2^32 / 2^12 = 2^20 pages; with 4-byte entries the page table is 4 MB per process, which is why multilevel (hierarchical) page tables, hashed page tables and inverted page tables are used. In two-level paging, the page number is split again into an outer index and an inner index.

Protection: each page-table entry has protection bits (read, write, execute) and a valid-invalid bit that marks whether the page is in the process's address space. Shared pages let several processes share one copy of read-only code.

## The TLB and effective access time
Every memory access with a page table needs two accesses (page table, then data). A translation look-aside buffer (TLB) is a small, fast associative cache of recent page-table entries.
EAT = h × (TLB time + memory time) + (1 − h) × (TLB time + 2 × memory time), where h is the TLB hit ratio.
Example: memory 100 ns, TLB 20 ns, hit ratio 80%: EAT = 0.8 × 120 + 0.2 × 220 = 96 + 44 = 140 ns. Many textbooks ignore the TLB time: EAT = h × m + (1 − h) × 2m.

## Segmentation
Segmentation matches the programmer's view: a program is a collection of segments (main program, functions, stack, arrays, symbol table), each with a name and length. A logical address is <segment number, offset>. The segment table holds a base and a limit for each segment; if offset < limit, physical address = base + offset, otherwise trap. Segmentation suffers from external fragmentation; many systems combine segmentation with paging.

## Common mistakes
- Forgetting to split a hole in variable-partition allocation, or splitting it in fixed partitions.
- Mixing up internal fragmentation (inside an allocated block) and external fragmentation (between blocks).
- Computing the offset with the wrong page size, or forgetting that physical address = frame × page size + offset.
- Counting only one memory access on a TLB miss.

## Viva questions
- Why does paging remove external fragmentation? Any free frame can hold any page, so free memory never has to be contiguous.
- What does the MMU do? Translates logical addresses to physical addresses at run time and checks protection.
- Which allocation strategy is fastest? First fit, because it stops at the first hole that fits.
